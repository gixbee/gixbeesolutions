# Full-Stack Audit — 2026-07-13

Scope: entire `backend/src` (NestJS) + `lib/` (Flutter). Findings grouped by severity.
Items marked **[FIXED]** were corrected in this pass; the rest are the prioritized backlog.

## CRITICAL — fixed in this pass

1. **[FIXED] Private user data leaked to any signed-in user.** Every endpoint that
   returned a User relation (booking customer/operator, job employer, rental owner/renter,
   support ticket user) shipped the raw entity — including `fcmToken` (lets attackers
   spoof pushes) and `walletBalance`. Fix: `@Exclude()` on both fields +
   global `ClassSerializerInterceptor` in `main.ts` strips them from every response.
2. **[FIXED] Double-settlement race on job completion.** Two concurrent completion-OTP
   verifies both passed the ACTIVE check → the customer's wallet could be debited twice.
   Fix: atomic conditional UPDATE claims ACTIVE→COMPLETED; only the winner settles.
3. **[FIXED] Wallet lost-update races.** `deductBookingFee`/`addFunds` were unlocked
   read-modify-write. Now transactional with pessimistic row locks (same pattern as
   `transferForBooking`, which was already correct).
4. **[FIXED] `mark-paid` had no authorization.** Any signed-in user could mark any
   booking paid. Now participants-only + must be COMPLETED.
5. **[FIXED] Socket listener leak (app).** The tracking screen registered a new
   `locationUpdated` handler on every open, never removed — stacked callbacks calling
   setState on dead screens. Fix: `off()` before `on()` + explicit unsubscribe in dispose.
6. **[FIXED] Background battery/data burn.** No lifecycle handling existed; the 5s
   worker pending-poll ran while the app was backgrounded. Fix: lifecycle observer
   pauses/resumes it. (Worker GPS streaming intentionally keeps running mid-job.)
7. **[FIXED] Leaked stream subscription** in MainWrapper (notifications listener
   never cancelled) and **ad-hoc Dio without timeouts** for Ola route calls
   (kept separate from the authed client on purpose — JWT must not reach Ola).
8. **[FIXED] `proTradesProvider` refetched static taxonomy on every screen open** —
   now cached with a 10-minute TTL.
9. **[FIXED] CORS `origin:'*'` + `credentials:true`** (invalid combo) — credentials
   flag removed (auth rides the Authorization header).

## HIGH — resolved after the initial report

- **[FIXED] N+1 / sequential awaits on the dispatch hot path.** `getNearby` awaited
  Redis location → snapshot → (miss) DB profile → status serially per candidate
  (up to ~60 round-trips before any pro was notified). Now: locations and snapshots
  resolve via `Promise.all`, and cache misses use ONE `IN (...)` query + parallel
  statuses. `getAll` workers likewise parallelized; `getVerificationQueue` now does
  a single `IN` talent query instead of one per pending worker.
- **[FIXED] Missing DB indexes.** Added: `bookings` (operator+status, customer+status,
  status+createdAt, plus FK indexes), `rental_reservations` (item+status,
  item+status+startTime — backs the overlap check — plus FKs), `job_posts`
  (isActive+createdAt, employer), `job_applications` (jobPost, applicant),
  `rental_items` (isAvailable+createdAt, owner), `worker_profiles` (verificationStatus).
- **[FIXED] Uncached read feeds.** `/hiring/jobs(+matched)`, `/rentals`, `/workers`,
  and the businesses admin list are Redis-cached (60s TTL) with write-through
  invalidation. NOTE: cached payloads are plain objects, so `stripPrivateFields()`
  (src/common/sanitize.ts) MUST run before caching — otherwise the @Exclude data-leak
  fix silently regresses.
- **[FIXED] Duplicate pollers per booking (app).** One shared
  `bookingStatusProvider` (5s, autoDispose, lifecycle-aware) replaces the three
  private timers in the tracking screen, home active-card and job-controls.

## HIGH — still open

- **`GET /bookings/my` runs two full queries and merges** (customer + operator),
  breaking pagination. → single query with OR.

## MEDIUM

- Unbounded `find()` (no `take`): rentals items/reservations, active jobs,
  wallet transactions, disputes, applications, `getRecommendedTalent`
  (loads ALL active workers on every job post, inside setImmediate).
- FCM sends serial in loops (broadcast fan-out ≤15, job-post matches, accept-cancel
  notifications) — a `sendToUsers` multicast already exists; use it / `Promise.all`.
- OTP verify is check-then-delete (tiny replay window) — use atomic GETDEL.
- Rental reserve/confirm overlap check is TOCTOU (not locked) — comment admits it;
  needs a transaction or exclusion constraint before real traffic.
- `submitRating` recomputes worker average non-atomically (concurrent ratings lose one).
- Images: no `cached_network_image`, no `cacheWidth` on list avatars; reels images
  load full-res; mock avatars call pravatar.cc.
- Heavy FutureProviders never refresh (banners/deals/workers/talent/rentals) —
  consider `.autoDispose` + pull-to-refresh coverage.

## LOW

- Swallowed wallet-fee failure has no reconciliation job (fee silently skipped).
- Per-second `setState` tickers rebuild whole screens (timer labels should be
  isolated widgets).
- `KEYS`-pattern cache invalidation (O(N) on Redis) in master-entries — fine now,
  replace with tagged sets at scale.
- Silent catch in job-timer init can leave the visible timer at 00:00 with no retry.
- `bookingPollIntervalSeconds = 3` is aggressive; socket events already cover accept.
- Stale `worker:status` Redis entry can mask busy→available for up to 1h if an
  event is missed.
